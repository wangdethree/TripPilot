## 非功能追踪

| 需求类别 | 主要验证方式 | 关联场景或门禁 |
| --- | --- | --- |
| `NFR-PERF-*` | 性能与并发测试 | `TS-022`、`TS-025`、性能基准报告 |
| `NFR-REL-*` | 故障注入、幂等、版本冲突与状态测试 | `TS-013`～`TS-015`、`TS-018`、`TS-022`、`TS-027`、`TS-030` |
| `NFR-SEC-*` | 安全测试、密钥扫描、越权测试 | `TS-020`、`TS-023`～`TS-025` |
| `NFR-PRIV-*` | 存储检查、删除测试、日志扫描 | `TS-019`～`TS-021` |
| `NFR-COST-*` | Token、调用次数和成本断言 | `TS-015`、`TS-024` |
| `NFR-OBS-*` | Trace 与指标契约测试 | 所有端到端评测场景 |
| `NFR-MAINT-*` | CI、覆盖率、契约测试 | 工程质量门禁 |
| `NFR-UX-*` | 交互验收与可访问性检查 | `TS-002`、`TS-004`、`TS-005`、`TS-022` |

## 覆盖规则

- 每个 `Must` 用户故事至少关联一个功能需求和一个端到端场景。
- 每个硬性业务规则至少具有一个失败场景。
- 每个终态至少具有一个验收场景。
- `Should` 功能在进入发布范围前必须补齐实现级验收。
- `Could` 功能不属于 v1.0 MVP 发布门禁。
