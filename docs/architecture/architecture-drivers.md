# 架构驱动因素

> 状态：In Review
>
> 候选基线：v1.0

架构驱动因素是会显著影响系统结构、技术方案或运行方式的需求。它们不是需求文档的复制，而是架构设计必须优先解决的约束。

## 关键质量属性

### 可控性

任何模型或工具调用都必须由工作流发起并受状态、权限、超时和资源预算约束。模型不能直接改变任务状态、写入数据库或访问任意网络地址。

### 正确性

金额、日期、时间重叠、活动数量、状态转换和版本号等结果必须可以使用固定输入重复验证。大模型可以提出候选值，但不能成为这些规则的最终判定者。

### 可恢复性

单个外部工具失败不应造成进程崩溃或任务永久运行。系统必须根据错误类别进入重试、缓存降级、`PARTIAL`、`NEEDS_USER_INPUT` 或 `FAILED`。

### 可测试性

工作流、领域规则和工具契约必须能够在不访问真实模型和真实旅行服务的情况下测试。所有非确定性边界都需要可替换实现。

### 可演进性

更换模型、工具服务商、存储实现或 Web 框架时，不应要求重写领域规则。只有经过实际容量或组织需求证明后，才考虑拆分微服务。

## 架构约束

- 第一版只设计一个 Agent 工作流，不采用多 Agent 协作。
- 第一版不执行预订、支付或其他外部高风险写操作。
- 服务端首先作为一个可部署单元交付。
- 数据库、模型和外部工具的具体产品在技术选型阶段决定。
- 客户端形态不应改变核心领域和工作流契约。

## 异步使用边界

| 适合异步执行 | 保持同步执行 |
| --- | --- |
| HTTP/API 请求处理 | 日期与天数计算 |
| 大模型请求 | 金额与预算计算 |
| 天气、地点和路线调用 | 时间线冲突检查 |
| 数据库 I/O | 约束优先级判断 |
| 取消信号和超时等待 | 状态转换合法性检查 |
| 可并行的独立外部查询 | 版本号与数据不变量 |

异步是处理等待和并发的机制，不承担业务规则判断。该边界用于限制 `asyncio` 的复杂度，防止异步代码扩散到纯领域逻辑。
