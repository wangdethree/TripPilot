# 产品简介：TripPilot

> 状态：Draft
>
> 阶段：Sprint 0
>
> 说明：本文件是待评审的产品草案，不是最终需求。

## 问题背景

自由行规划需要同时处理用户偏好、预算、日期、地点距离、天气和开放时间等信息。信息分散且约束容易冲突，用户通常需要反复搜索并手工调整行程。

## 产品目标

TripPilot 希望通过受控的 Agent 工作流，组合旅行信息工具，生成可解释、可检查、可局部调整的多日旅行计划。

## 初步目标用户

计划国内城市 1～3 日自由行，希望快速获得个性化行程草案的用户。

## 第一版核心能力

1. 将用户旅行描述转换为结构化需求。
2. 获取或读取候选景点、天气、路线和费用信息。
3. 根据偏好与约束生成多日行程。
4. 检查预算、时间、距离和天气冲突。
5. 根据检查结果或用户反馈重新规划。

## 非目标

1. 不执行真实机票、酒店、门票购买或支付。
2. 不承诺替代官方渠道提供安全、签证或实时营业信息。
3. 第一版不追求覆盖所有国家、城市和旅行类型。
4. 第一版不采用多 Agent 或微服务架构。
