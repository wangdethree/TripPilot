# 05：测试与 Agent 评测

## [必须掌握] 三类验证不能混淆

| 类型 | 回答的问题 | TripPilot 示例 |
| --- | --- | --- |
| 单元测试 | 一个规则/对象是否正确 | 金额精度、预算、状态迁移 |
| 集成测试 | 多个组件的契约是否能协作 | FastAPI 完整流程、迁移 Metadata |
| Agent Eval | 概率系统在场景集合上的质量是否达标 | 需求理解、工具选择、约束满足、幻觉 |

测试通过不代表 Agent 质量高；主观体验好也不代表边界规则正确。

## [必须掌握] 确定性硬门禁

以下内容不应交给“模型评分”：

- Schema 是否有效；
- 已知硬约束是否失败；
- 未知费用是否被算成 0；
- 来源和查询时间是否存在；
- 重规划是否超过上限；
- Token/密钥是否泄漏；
- 幂等、版本、取消和终态是否正确。

这些用普通断言得到 0/1 结论。

## [必须掌握] 60 场景数据集

`evals/scenarios-v1.jsonl` 包含：

- 12 条正常规划；
- 10 条需求补全；
- 12 条约束与重规划；
- 10 条工具失败；
- 8 条局部修改与版本；
- 8 条安全与资源控制。

当前 `trippilot-eval` 执行的是 **Level 0 数据集契约门禁**：字段完整、ID 唯一、分类数量满足基线。它不会假装已执行所有真实模型场景。

```bash
uv run trippilot-eval
```

## [应该理解] 分层评测

### Level 0：数据集契约

每次 CI 都运行，证明数据集可读取、覆盖数量不退化。

### Level 1：确定性离线回归

由 pytest、Fake Model 和 Fake Tools 执行，当前覆盖核心规划、约束、工具失败、API 幂等、取消语义和数据库租约。无网络、便宜、稳定。

### Level 2：真实适配器评测

使用受保护密钥，检查 OpenAI 结构化输出和真实旅行工具契约。不能在外部 PR 自动运行，避免密钥和费用风险。

### Level 3：人工质量评审

对可执行性、路线合理性、个性化、清晰度、风险表达打分。LLM 可以辅助，但发布结论由人确认。

## [应该理解] Eval 版本化

评测报告必须关联：

- 代码 Commit；
- 数据集版本；
- Prompt 和 Schema 版本；
- 请求模型与实际模型；
- 工具版本；
- 延迟、Token、调用次数和成本。

否则一次“90 分”无法复现，也无法判断升级后是否退化。
