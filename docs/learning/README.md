# TripPilot 学习路线

这套材料不是要求你先看完再写项目，而是项目已经提供了可运行样本，你按“运行 → 定位代码 → 修改 → 测试 → 解释”的方式学习。每一章都直接指向 TripPilot 的代码。

## 知识等级

- **[必须掌握]**：秋招面试中应能脱离文档解释，并能独立修改对应代码。
- **[应该理解]**：应能说明为什么这样设计、有哪些权衡，允许查 API 细节。
- **[拓展了解]**：知道适用场景和关键词即可，入职后再深入。

## 你真正需要掌握的主线

```mermaid
flowchart LR
    A["自然语言需求"] --> B["结构化 RequirementDraft"]
    B --> C["用户确认边界"]
    C --> D["LangGraph 有限状态图"]
    D --> E["地点 / 天气工具"]
    E --> F["模型生成候选计划"]
    F --> G["确定性约束检查"]
    G -->|"失败且未到上限"| F
    G -->|"通过或部分未知"| H["TripPlan + 来源 + 预算"]
```

你不需要背诵框架 API。你需要掌握的是每个箭头的输入、输出、失败方式、状态变化和测试方法。

## 学习节奏

每次学习 60～90 分钟：

1. 先运行一个测试或完整流程。
2. 只阅读该流程涉及的 3～5 个文件。
3. 用自己的话画出数据流。
4. 修改一个小行为并补测试。
5. 回答本章“自检问题”。
6. 恢复或提交修改。

遇到不懂的地方可以直接问：“`load_context` 为什么用并发？”、“`PARTIAL` 和 `FAILED` 有什么区别？”或者“请带我逐行读这个测试”。不必先把问题组织成专业术语。
