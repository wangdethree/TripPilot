# ADR-0007：长任务采用 REST 命令与状态轮询

> 状态：Proposed
>
> 日期：2026-07-28

## 背景

完整规划可能持续数十秒，并且会暂停等待确认或用户决策。单个 HTTP 请求持续到任务完成会增加超时、断线重试和重复执行风险。WebSocket 又会增加连接状态和部署复杂度。

## 决策

第一版使用 REST 命令创建或推进任务，并使用不透明任务令牌轮询任务状态。

- 创建、确认和修改返回 `202 Accepted`。
- 客户端使用 `GET` 查询权威状态，并遵循 `Retry-After`。
- 写命令支持 `Idempotency-Key`。
- 任务和行程访问令牌通过 Authorization Header 发送。
- 局部修改使用 `ETag` 与 `If-Match` 防止版本覆盖。
- SSE 可以作为非关键体验增强，但不得成为正确性的前提。

## 备选方案

### 同步 HTTP

实现简单，但无法稳定满足首次反馈、长任务恢复和等待用户确认。

### WebSocket

实时双向通信更自然，但连接恢复、负载均衡和状态一致性成本更高；业务仍然需要持久化任务。

### 仅使用 SSE

适合服务端进度推送，但用户命令仍需普通 HTTP，而且断线后仍需查询权威状态。

## 影响与后果

- 客户端需要轮询、退避和结果状态停止逻辑。
- 服务端必须控制查询频率和提供建议间隔。
- API 可以在未来无破坏地增加 SSE。
- 不透明令牌需要客户端安全存储和日志脱敏。
