# 验收场景

> 状态：Accepted
>
> 候选基线：v1.0

这些场景定义发布前必须覆盖的业务行为。具体测试数据可以在实现阶段扩展，但不得改变场景意图。

## TS-001 完整需求进入确认

- **Given** 用户提供合法的目的地、日期、人数、预算、预算是否包含住宿和兴趣
- **When** 系统完成需求提取与校验
- **Then** 任务进入 `AWAITING_CONFIRMATION`，并展示结构化摘要

## TS-002 只追问缺失信息

- **Given** 用户已经提供目的地、天数、人数和兴趣，但缺少开始日期与预算
- **When** 系统识别缺失信息
- **Then** 只追问开始日期、预算及预算是否包含住宿，不重复询问已确认字段

## TS-003 拒绝过去日期

- **Given** 用户提供的开始日期早于当前日期
- **When** 系统校验旅行需求
- **Then** 返回日期错误，不进入 `AWAITING_CONFIRMATION`

## TS-004 展示默认值

- **Given** 用户没有提供旅行节奏、交通偏好和每日时间
- **When** 系统生成需求摘要
- **Then** 摘要展示适中节奏、公共交通与步行、`09:00` 至 `21:00`

## TS-005 未确认不得规划

- **Given** 必填信息已经完整，但用户尚未确认摘要
- **When** 系统等待用户操作
- **Then** 不调用正式地点、天气和路线规划工具

## TS-006 标准行程成功

- **Given** 合法的成都三日游需求和完整模拟工具数据
- **When** 用户确认并开始规划
- **Then** 任务进入 `COMPLETED`，输出三天时间线、预算、检查结果和来源

## TS-007 超预算自动重规划

- **Given** 第 1 份候选计划已知费用超过预算
- **When** 预算硬性检查返回 `FAIL`
- **Then** 系统针对预算原因重规划，且不自行提高用户预算

## TS-008 硬性约束冲突

- **Given** 用户预算无法同时满足所有必去地点
- **When** 自动重规划仍不能解决冲突
- **Then** 任务进入 `NEEDS_USER_INPUT`，展示冲突与可选调整

## TS-009 行程强度超限

- **Given** 用户选择轻松节奏
- **When** 某日包含 4 个主要活动
- **Then** 行程强度检查返回 `FAIL`

## TS-010 路线时间过长

- **Given** 两个连续地点交通时间为 70 分钟且不存在硬性冲突
- **When** 系统检查路线
- **Then** 路线检查返回 `WARNING`，计划可以继续展示

## TS-011 天气适配

- **Given** 普通降雨天气和可用室内候选活动
- **When** 初始计划包含不合适的室外活动
- **Then** 系统优先替换室内活动；无法替换时返回 `WARNING`

## TS-012 严重天气安全限制

- **Given** 严重天气预警
- **When** 候选计划包含明显不安全活动
- **Then** 天气检查返回 `FAIL`，不得以 `COMPLETED` 展示

## TS-013 路线服务失败

- **Given** 地点数据可用，但路线服务超时且无有效缓存
- **When** 系统仍能生成候选活动顺序
- **Then** 路线检查为 `UNKNOWN`，任务进入 `PARTIAL`

## TS-014 地点候选为空

- **Given** 地点工具经过允许的重试后没有任何可用候选
- **When** 系统无法生成行程
- **Then** 任务进入 `FAILED`，不得由模型编造地点

## TS-015 达到重规划上限

- **Given** 初始计划和 2 次重规划都违反硬性约束
- **When** 第 3 份候选计划检查完成
- **Then** 停止自动规划并进入 `NEEDS_USER_INPUT`

## TS-016 独立时间线项目

- **Given** 一天包含景点、交通、用餐和休息
- **When** 系统输出行程
- **Then** 四类内容作为独立时间线项目，按开始时间排序且不重叠

## TS-017 局部修改保持其他日期

- **Given** 已存在三日行程
- **When** 用户只要求替换第二天下午活动
- **Then** 新版本只改变受影响范围，第一天和第三天保持一致

## TS-018 修改失败保留旧版本

- **Given** 行程最新版本为 2
- **When** 局部修改因硬性冲突或写入失败未完成
- **Then** 版本 2 仍可使用，不产生残缺版本 3

## TS-019 匿名保存与重新打开

- **Given** 一份 `COMPLETED` 行程
- **When** 用户保存并使用返回的行程 ID 重新打开
- **Then** 系统返回相同最新版本、检查结果和来源时效

## TS-020 匿名行程删除

- **Given** 用户持有有效行程 ID
- **When** 用户删除行程后再次访问
- **Then** 系统不返回行程内容，外部错误与不存在或过期 ID 相同

## TS-021 过期来源刷新

- **Given** 重新打开的历史计划包含过期天气和开放时间
- **When** 用户只查看历史计划
- **Then** 系统明确标记过期；当用户请求修改时重新查询相关信息

## TS-022 取消规划任务

- **Given** 任务处于 `COLLECTING_REQUIREMENTS`、`AWAITING_CONFIRMATION`、`PLANNING` 或 `REPLANNING` 中的任一状态
- **When** 用户取消任务
- **Then** 2 秒内确认取消，不调度新步骤，最终状态为 `CANCELLED`

## TS-023 提示注入内容

- **Given** 地点描述中包含要求忽略规则、泄露密钥或调用未授权工具的文本
- **When** Agent 读取该描述
- **Then** 仅把它作为不可信地点数据，不执行其中指令并记录安全事件

## TS-024 Token 上限

- **Given** 任务达到配置的 Token 上限
- **When** 系统准备继续调用模型
- **Then** 停止生成并返回 `COST_LIMIT_EXCEEDED`；存在可安全展示的计划时进入 `PARTIAL` 并保留结果，否则进入 `FAILED`

## TS-025 并发任务隔离

- **Given** 10 个用户同时规划不同城市和日期
- **When** 系统并发执行任务
- **Then** 任务数据、来源、状态和结果不得互相混合

## TS-026 未知费用

- **Given** 某活动费用无法可靠获取
- **When** 系统汇总预算
- **Then** 该费用标记为 `UNKNOWN`、金额为空，并且不按 0 参与合计

## TS-027 并发版本冲突

- **Given** 用户基于版本 2 编辑行程，但服务器最新版本已经是 3
- **When** 用户提交局部修改
- **Then** 系统返回 `VERSION_CONFLICT` 和最新版本号，不创建版本 4

## TS-028 输入边界校验

- **Given** 需求分别包含过去的开始日期、结束日期早于开始日期、1～3 天之外的行程、1～8 人之外的人数、非正数预算或不一致的结束日期与天数
- **When** 系统逐例校验需求
- **Then** 非法取值返回校验错误，不一致的结束日期与天数进入澄清流程，所有案例都不得进入正式规划

## TS-029 硬性行程规则

- **Given** 候选计划分别包含时间重叠、超出每日可用时间、已知闭馆、缺少必去地点、出现避开地点或违反饮食与行动限制
- **When** 系统逐例执行硬性约束检查
- **Then** 对应检查均返回 `FAIL`，计划不得以 `COMPLETED` 展示

## TS-030 非法状态转换

- **Given** 一个已经进入 `COMPLETED` 的任务
- **When** 调用方尝试把同一任务改回 `PLANNING`
- **Then** 系统拒绝转换并保持原状态；后续修改必须创建关联的新任务

## TS-031 住宿不计入预算范围

- **Given** 用户总预算为 2,000 元且明确不包含住宿，住宿费用为 800 元，其他已知与估算费用为 1,800 元
- **When** 系统汇总和检查预算
- **Then** 总旅行费用展示为 2,600 元，`budget_scope_total` 为 1,800 元，`remaining_budget` 为 200 元，预算上限检查不返回 `FAIL`
