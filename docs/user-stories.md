# 用户故事与优先级

> 状态：Accepted
>
> 阶段：Sprint 0

优先级采用 MoSCoW：

- `Must`：第一版不具备就不能形成完整产品闭环。
- `Should`：重要，但不阻塞第一版核心闭环。
- `Could`：有价值的增强功能。
- `Won't`：当前版本明确不做。

## Must

### US-001 描述旅行需求

作为一名短途自由行用户，我希望使用自然语言描述目的地、日期、人数、预算和兴趣，以便不填写复杂表单也能开始规划。

关联需求：`FR-001`、`FR-002`、`FR-003`

### US-002 补全缺失信息

作为一名没有一次说清所有需求的用户，我希望 Agent 只追问缺失或有歧义的信息，以便逐步完善需求而不必重复回答。

关联需求：`FR-004`、`FR-005`、`FR-006`、`FR-017`

### US-003 获得结构化行程

作为一名准备出行的用户，我希望获得包含时间、地点、交通、费用和注意事项的多日行程，以便按照计划实际出行。

关联需求：`FR-007`、`FR-008`、`FR-009`

### US-004 获得预算明细

作为一名预算有限的用户，我希望查看每日费用、分类费用、未知费用和预留金额，以便判断行程是否在承受范围内。

关联需求：`FR-010`

### US-005 检查行程约束

作为一名不擅长规划路线的用户，我希望系统检查预算、时间、路线、天气、开放时间和行程强度，以便在出发前发现不合理安排。

关联需求：`FR-011`、`FR-012`

### US-006 自动重新规划

作为一名获得了不合格初始计划的用户，我希望 Agent 在发现硬性约束冲突后自动调整计划，以便最终得到满足核心要求的行程。

关联需求：`FR-014`

### US-007 局部修改行程

作为一名已经基本认可行程的用户，我希望只修改指定日期或活动，以便不破坏其他已经满意的安排。

关联需求：`FR-013`、`FR-024`

### US-008 了解信息可信度

作为一名依赖动态旅行信息的用户，我希望看到信息来源、查询时间和不确定项，以便出发前核实可能变化的内容。

关联需求：`FR-012`、`FR-023`

### US-009 外部服务失败时获得解释

作为一名正在等待规划的用户，我希望在天气、路线或景点服务失败时获得明确提示和可用的降级结果，以便判断是否继续使用当前计划。

关联需求：`FR-015`、`FR-018`

### US-013 取消规划任务

作为一名不想继续等待或改变主意的用户，我希望取消正在执行的规划任务，以便停止后续模型和工具调用。

关联需求：`FR-019`

## Should

### US-010 保存和继续修改行程

作为一名需要多次调整计划的用户，我希望保存行程并通过行程 ID 重新打开，以便之后继续修改。

关联需求：`FR-016`、`FR-023`

第一版不提供账号注册与登录，通过不可预测的行程 ID 访问匿名行程。

### US-014 删除匿名行程

作为一名已经不再需要行程的用户，我希望删除通过行程 ID 保存的数据，以便控制旅行信息的保留。

关联需求：`FR-022`

## Could

### US-011 地图展示

作为一名关注路线是否合理的用户，我希望在地图上查看每天的地点和顺序，以便直观判断路线。

关联需求：`FR-020`

### US-012 导出行程

作为一名准备出发的用户，我希望将行程导出为便于分享或离线查看的文件，以便与同行者共享。

关联需求：`FR-021`

## Won't

当前版本明确不包含：

- 用户注册与登录
- 机票、酒店、门票和餐厅自动预订
- 真实支付
- 国外旅行和签证规划
- 复杂跨城市长途旅行
- 语音助手
- 多 Agent 协作

## MVP 核心闭环

```text
用户描述需求
→ Agent 提取信息
→ Agent 追问缺失信息
→ 获取旅行数据
→ 生成结构化行程
→ 检查约束
→ 自动重新规划
→ 展示预算与来源
→ 用户局部修改
```
