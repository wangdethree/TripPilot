# 非功能需求

> 状态：Accepted
>
> 候选基线：v1.0
>
> 测量环境：除非特别说明，性能指标在测试或预发布环境、外部依赖健康、单个城市 1～3 日行程条件下测量。

## 性能

### NFR-PERF-001 首次反馈

用户开始规划后，系统应在 2 秒内返回任务 ID、当前状态或进度提示，不得让用户在无反馈状态下等待完整计划。

### NFR-PERF-002 需求提取延迟

自然语言需求提取与结构化校验的第 95 百分位响应时间不超过 8 秒。

### NFR-PERF-003 完整规划延迟

- 外部依赖健康时，首次完整规划的第 95 百分位完成时间不超过 60 秒。
- 单次规划任务硬超时为 120 秒。
- 达到硬超时后，任务必须进入 `PARTIAL`、`FAILED` 或 `NEEDS_USER_INPUT`，不得无限运行。

### NFR-PERF-004 行程读写延迟

匿名行程保存和重新打开的第 95 百分位响应时间不超过 1 秒，不包含首次动态信息刷新时间。

### NFR-PERF-005 取消响应

用户发出取消请求后，系统应在 2 秒内确认取消意图并停止调度新的步骤。

### NFR-PERF-006 基础并发

在 10 个并发完整规划任务的基准测试中：

- 任务数据不得串扰。
- 服务不得崩溃或出现无法终止的任务。
- 至少 95% 的任务应在 120 秒硬超时内到达终态或 `NEEDS_USER_INPUT`。

## 可靠性

### NFR-REL-001 终态保证

每个已开始的任务最终必须进入 `COMPLETED`、`PARTIAL`、`NEEDS_USER_INPUT`、`FAILED` 或 `CANCELLED`，不得永久停留在执行中状态。

### NFR-REL-002 外部工具超时

- 单次只读外部工具调用默认超时不超过 8 秒。
- 单个工具在一次规划步骤中的累计等待时间不超过 20 秒。
- 超时值必须可按工具配置。

### NFR-REL-003 有限重试

- 只对超时、限流和服务端临时错误等可恢复故障重试。
- 每次只读调用最多重试 2 次。
- 参数错误、权限错误、确定性无结果不得重试。
- 重试必须记录次数、原因和最终结果。

### NFR-REL-004 原子版本写入

创建新行程版本时，要么完整写入需求快照、计划、检查结果、来源和变更记录，要么全部失败。写入失败不得破坏上一可用版本。

### NFR-REL-005 故障注入

天气、地点、路线、模型和持久化服务的模拟故障场景必须 100% 到达预期任务状态，不得出现未处理异常或虚构降级数据。

### NFR-REL-006 幂等性

重复提交同一保存或取消请求不得创建重复版本，也不得产生相互矛盾的终态。

### NFR-REL-007 并发版本控制

局部修改必须携带其基于的行程版本。目标行程已经产生新版本时，系统返回 `VERSION_CONFLICT`，不得使用旧版本静默覆盖新版本。

### NFR-REL-008 可用性目标

正式演示环境的服务端 API 月度可用性目标为 99.0%，不包含提前公布的维护窗口。外部服务失败后返回符合契约的 `PARTIAL`、`NEEDS_USER_INPUT` 或 `FAILED` 结果视为系统可用；连接失败、无响应和未处理异常视为不可用。

## 安全

### NFR-SEC-001 工具最小权限

- Agent 只能调用显式注册且属于允许列表的工具。
- 第一版工具只允许查询和项目内部数据写入。
- 不提供预订、支付、发消息或其他高风险外部写操作。
- 工具参数在执行前必须经过结构化校验。

### NFR-SEC-002 出站访问控制

外部工具只能访问配置允许的数据服务域名，不得直接请求用户或网页内容提供的任意 URL，避免服务端请求伪造和越权访问。

### NFR-SEC-003 提示注入防护

- 网页、地点描述、搜索结果和工具输出一律视为不可信数据。
- 外部内容不得修改系统规则、扩大工具权限或要求泄露配置。
- 检测到疑似指令型外部内容时，应忽略其指令语义并记录安全事件。

### NFR-SEC-004 密钥管理

- API Key、Token 和数据库凭证只能从运行环境的密钥配置读取。
- 密钥不得写入仓库、Prompt、响应、Trace 或普通日志。
- `.env` 必须被 Git 忽略，仓库只保存不含真实值的 `.env.example`。

### NFR-SEC-005 匿名行程标识

- 匿名行程 ID 必须由安全随机源生成，并至少具有 128 位不可预测性。
- 行程 ID 作为访问凭证使用，不得使用自增数字或可枚举格式。
- 不存在、已过期和已删除的 ID 返回相同外部错误，避免探测记录存在性。

### NFR-SEC-006 限流与资源配额

- 每个客户端默认每小时最多创建 20 个完整规划任务。
- 并发规划任务默认不超过 3 个。
- 限制值必须可配置，并在超出时返回稳定错误码和重试建议。

### NFR-SEC-007 推理信息边界

系统可以展示工具调用、状态变化、约束证据和简要决策理由，但不得向用户或日志输出模型隐藏推理链。

### NFR-SEC-008 依赖与代码检查

发布门禁必须包含依赖漏洞检查、静态检查和密钥扫描。发现未处置的高严重度问题时不得发布。

## 隐私

### NFR-PRIV-001 最小化存储

匿名保存默认只持久化已确认的结构化需求、计划版本、来源、检查结果和必要变更摘要，不持久化完整原始对话。

### NFR-PRIV-002 敏感旅行信息

精确旅行日期、同行情况、住宿区域、行动限制和饮食限制按敏感业务数据处理，不得写入公开日志、错误响应或分析事件的自由文本。

### NFR-PRIV-003 保留期限

- 匿名行程默认保留 30 天。
- 到期后自动删除行程及其版本。
- 每次成功重新打开行程可以将保留期限延长至最近访问后的 30 天。
- 保留策略必须在保存时向用户说明。

### NFR-PRIV-004 用户删除

持有有效行程 ID 的用户可以删除匿名行程。删除成功后，该 ID 不得再返回行程内容。

### NFR-PRIV-005 日志脱敏

日志和 Trace 必须移除密钥、完整行程 ID、精确住宿地址、完整用户自然语言输入及其他不必要的敏感数据。

## 成本与资源控制

### NFR-COST-001 模型调用上限

一次完整规划任务默认最多调用大模型 10 次，包括需求提取、计划生成和自动重规划。限制必须可配置。

### NFR-COST-002 工具调用上限

一次完整规划任务默认最多执行 20 次外部工具调用。缓存命中不计为外部调用。

### NFR-COST-003 Token 上限

一次完整规划任务默认总 Token 上限为 40,000。达到上限时停止继续生成并返回 `COST_LIMIT_EXCEEDED`：

- 已有计划能够安全展示时，任务进入 `PARTIAL` 并保留该结果。
- 没有可安全展示的计划时，任务进入 `FAILED`。

### NFR-COST-004 成本记录

每次任务记录模型标识、模型版本、Prompt 版本、输入与输出 Token、工具调用次数、缓存命中和估算费用。费用计算使用带版本的价格配置，不把模型价格写死在业务代码中。

## 可观测性

### NFR-OBS-001 结构化事件

每次任务至少记录以下结构化事件：

- 任务开始与终止
- 状态变化
- 候选计划次数
- 工具名称、结果状态、延迟和重试次数
- 约束检查结果
- 模型与 Prompt 版本
- Token 和估算成本
- 稳定错误码

事件必须包含 `trace_id` 和脱敏后的 `task_id`，但不得包含隐藏推理链或敏感原文。

### NFR-OBS-002 核心指标

系统至少提供以下指标：

- `COMPLETED`、`PARTIAL`、`NEEDS_USER_INPUT`、`FAILED`、`CANCELLED` 比例
- 需求提取与完整规划延迟
- 自动重规划次数
- 工具成功率、超时率和缓存命中率
- 硬性约束违规拦截次数
- Token 和单任务估算成本

### NFR-OBS-003 可复现标识

评测或故障分析必须能够定位到代码版本、Prompt 版本、模型版本、工具版本和评测数据集版本。

## 可维护性与工程质量

### NFR-MAINT-001 模块契约

需求模型、计划模型、工具输入输出和错误必须使用显式 Schema。模拟工具和真实工具必须通过相同契约测试。

### NFR-MAINT-002 确定性逻辑

金额计算、日期计算、时间重叠、活动数量、状态转换和版本号等确定性规则不得依赖大模型判断。

### NFR-MAINT-003 自动化测试覆盖

- 预算、日期、时间线、状态转换、约束检查和版本管理等核心确定性模块行覆盖率不低于 90%。
- 项目整体行覆盖率不低于 80%。
- 所有 `Must` 用户故事至少有一个端到端验收场景。

### NFR-MAINT-004 持续集成门禁

合并到 `main` 前必须通过格式检查、静态检查、类型检查、单元测试、集成测试、Agent 回归评测和密钥扫描。

### NFR-MAINT-005 可复现环境

依赖版本必须锁定；本地、CI 和容器环境使用同一依赖来源，保证从干净环境可以重复安装和运行测试。

### NFR-MAINT-006 文档同步

影响需求、业务规则、Schema、API、Prompt 或外部工具契约的变更，必须同时更新相应文档和追踪关系。

## 易用性与可访问性

### NFR-UX-001 可操作错误

用户可见错误必须说明发生了什么、哪些内容仍然可用以及下一步可以采取什么操作，不得只返回内部异常文本。

### NFR-UX-002 默认值透明

系统采用的所有默认值和假设必须在首次规划确认前展示，并允许用户修改。

### NFR-UX-003 进度透明

长任务应展示当前业务阶段，例如“正在查询天气”“正在检查路线”，不得展示伪造进度百分比。

### NFR-UX-004 状态不仅依赖颜色

`PASS`、`WARNING`、`FAIL` 和 `UNKNOWN` 必须同时使用文字或图标表达，不能只依赖颜色。

### NFR-UX-005 键盘操作

核心流程中的输入、确认、取消、重新规划和保存操作应可以通过键盘完成。
