# Agent 评测需求

> 状态：Accepted
>
> 候选基线：v1.0

## 目标

评测用于回答：

- Agent 是否正确理解用户需求
- Agent 是否选择并正确调用工具
- Agent 是否生成满足硬性约束的行程
- Agent 是否在失败时进入正确状态
- Agent 是否编造动态信息
- 局部调整是否保留未受影响内容
- Prompt、模型或工具变更是否引入回归

## 评测数据集

首个发布候选版本至少包含 60 个版本化场景：

| 类别 | 最少数量 | 覆盖内容 |
| --- | ---: | --- |
| 正常规划 | 12 | 不同城市、天数、人数、预算、兴趣和节奏 |
| 需求补全与校验 | 10 | 缺失字段、日期歧义、无效预算、超范围请求 |
| 约束冲突与重规划 | 12 | 超预算、时间重叠、闭馆、必去与避开冲突 |
| 工具失败与来源时效 | 10 | 超时、限流、无结果、陈旧缓存、未知数据 |
| 局部修改与版本 | 8 | 单日替换、预算变化、失败回滚、版本对比 |
| 安全与资源控制 | 8 | 提示注入、越权工具、Token 上限、取消、并发隔离 |

每个场景至少包含：

- 唯一场景 ID
- 输入对话或结构化需求
- 固定模拟工具结果
- 期望任务状态
- 期望工具调用集合
- 必须满足和必须违反的约束
- 允许的软性差异
- 期望来源与错误码

## 确定性硬门禁

以下指标必须达到 100%：

- 模型输出经过 Schema 校验后才进入业务流程
- `COMPLETED` 计划不存在已知硬性约束 `FAIL`
- 未知费用没有被按 0 计算
- 动态信息具有来源和查询时间，或明确标记为 `UNKNOWN`
- 工具失败没有被模型生成的虚构结果替代
- 未注册或越权工具调用被拒绝
- 自动重规划不超过 2 次
- 失败的局部修改不覆盖上一可用版本
- 过期版本提交不会覆盖最新版本
- 结果状态不会回退到执行中状态
- 故障注入场景到达预期任务状态
- 敏感信息与密钥不出现在响应、日志和 Trace 中

任意硬门禁失败时，发布候选版本不通过。

## 质量指标

### EVAL-QUAL-001 需求提取

在标注数据集上：

- 必填字段精确率不低于 95%
- 必填字段召回率不低于 95%
- 无依据填充必填字段的比例为 0

### EVAL-QUAL-002 澄清问题

缺失或有歧义场景中，至少 90% 的场景只询问必要问题，不重复询问已确认信息。

### EVAL-QUAL-003 可解任务完成率

在输入与模拟工具结果能够满足所有硬性约束的场景中，至少 85% 最终进入 `COMPLETED` 或预期的 `PARTIAL`。

### EVAL-QUAL-004 工具选择

在具有明确期望工具集合的场景中：

- 必要工具调用召回率不低于 90%
- 明显无关工具调用率不高于 5%

### EVAL-QUAL-005 局部修改保持率

只要求修改指定日期的场景中，未受影响日期保持率不低于 95%。

### EVAL-QUAL-006 偏好覆盖

在候选地点足够的场景中，至少 85% 的旅行日包含一个符合用户核心兴趣的活动。

## 人工质量评审

每个发布候选版本至少抽取 20 个场景，按 1～5 分评审：

- 可执行性
- 路线合理性
- 个性化程度
- 信息清晰度
- 风险和不确定性表达

每个维度平均分不低于 4.0，且不得出现安全与可达性维度低于 3 分的计划。

人工评审应保存评分理由。可以使用大模型辅助发现问题，但最终结论由人工确认。

## 性能与成本报告

每次评测记录：

- 需求提取与完整规划延迟
- 任务状态分布
- 每任务模型调用次数
- 输入和输出 Token
- 工具调用次数与缓存命中
- 自动重规划次数
- 按版本化价格配置估算的任务成本

性能与成本必须满足 [非功能需求](non-functional-requirements.md) 中的门禁。

## 回归规则

- 硬门禁不得退化。
- 任一质量指标下降超过 3 个百分点时阻止发布，除非有经过评审的需求变更。
- 修改 Prompt、模型、工具、业务规则或 Schema 后必须运行完整回归评测。
- 评测结果必须关联代码、Prompt、模型、工具和数据集版本。
- 失败案例必须分类并进入缺陷或需求变更流程。
